# Taste
- Expects the agent to read the project's guidance file (e.g. `AGENTS.md`) before starting a task and to follow its conventions. Confidence: 0.65
- Prefers reusable UI graphics stored as standalone SVG asset files in a theme directory (e.g. `theme/default/`) rather than drawn inline in QML. Confidence: 0.6
- Prefers interactive UI highlights (e.g. focus borders) to use the theme accent color rather than arbitrary colors. Confidence: 0.55
- Prefers KDE Frameworks (KF6) libraries for KDE desktop integration rather than reimplementing desktop logic (e.g. wants KApplicationTrader/KIO for app launching and MIME associations). Confidence: 0.75
- Prefers using standard freedesktop/XDG desktop portals when available (e.g. `org.freedesktop.portal.OpenURI`/`OpenFile` for launching files) and keeping custom implementations only as a fallback for when the portal is unavailable or fails. Confidence: 0.7
- Expects features to follow freedesktop/XDG standards (e.g. writing defaults to `~/.config/mimeapps.list` via standard mechanisms so both KDE and GLib honor them) rather than custom or desktop-specific formats. Confidence: 0.65
- Prefers the focus indicator/border to appear only from directional navigation (keyboard arrows / d-pad / stick) — not from mouse clicks, and not merely from entering a folder; an item should only show the border when it is an explicitly intended target (e.g. the folder you went Up out of) or once directional navigation has begun. Confidence: 0.7
- Prefers controller actions to target the currently focused element rather than the mouse/cursor position — e.g. the context-menu button *and* the keyboard Menu key open the menu for the focused item, not at the cursor. Confidence: 0.65
- Expects keyboard input to be unified with controller input: a keyboard key should behave exactly like its gamepad counterpart and route through the same code path rather than a separate implementation. Confidence: 0.6
- Prefers action labels/menu items to be specific and informative, reflecting the actual target (e.g. "Open with <AppName>" naming the system default application and its icon) rather than a generic "Open". Confidence: 0.6
- In selection mode, expects the accept/Enter key to toggle the focused item's selection (like Space) instead of opening it. Confidence: 0.55
- Expects controller/gamepad input to be routed to popup UI (menus, context menus, dialogs) while a popup is open — popups should take over navigation when they appear instead of the controller continuing to drive the background view. Confidence: 0.6
- Prefers adopting a mature, well-established library/dependency (e.g. a standard game-input crate like `gilrs` with SDL controller mapping) over maintaining hand-rolled low-level implementations when a subsystem gets complicated. Confidence: 0.5
- This project follows a no-committed-tests convention: temporary local tests are acceptable for verifying a fix, but they must be removed before finishing (relying on build/format checks plus a timed runtime run instead). Confidence: 0.6
- Expects the agent not to terminate processes it did not start — verify ownership (e.g. via `/proc`, parent shell, cmdline) before killing, and leave the user's own running app instances untouched. Confidence: 0.55
- Prefers view/layout behaviors to be exposed as documented, user-facing config options (defaults in `config/default.cfg`, parsed into the Rust config, mirrored in `plugins.qmltypes`) and changeable from the GUI (e.g. the View menu), rather than hardcoded. Confidence: 0.7
- Prefers per-folder view/sort settings to be scoped to the folder (the "Here" tab) and not offered globally when they only make sense locally — e.g. FREE sort can only be enabled for the current folder, never the global config. Confidence: 0.5
- For the folder grid, prefers FILL alignment to center the grid block when it is smaller than the viewport and clamp to the start when it overflows (respecting an explicit Lines value), rather than stretching gaps or auto-fitting. Confidence: 0.5
- Prefers numeric config values to use 0 as a sentinel meaning "auto / fit to the available screen size" (e.g. Lines = 0 auto-fits the window). Confidence: 0.45
- Prefers focus-driven viewport scrolling to be smooth/animated (eased transitions) rather than instant jumps when navigating. Confidence: 0.5
- Wants the focused item kept centered in the viewport as a (configurable) navigation behavior rather than only nudging it into view. Confidence: 0.45
- Expects content layout to reserve space for overlay elements (e.g. scrollbars) so grid items can never render under or overlap them — overlap is treated as a bug, including at scroll extremes and with alignment applied. Confidence: 0.5
- Expects theme assets (e.g. SVGs under `theme/default/`) to take effect immediately when edited on disk, without a rebuild — compiled-in/embedded copies and caches keyed only on something other than the artwork (e.g. just the colour) are treated as defects. Confidence: 0.45
- Prefers directional/grid navigation to be geometry-aware: movement stays within a row/column and stops at the real grid edge (a Right at the end of a row does nothing, rather than wrapping to the next row), and hitting an edge hands focus to the adjacent view in that direction — crossing should work from any edge position, not only after reaching the very last item. Confidence: 0.55
- In a window with multiple panes/views, prefers each pane to claim only the space its content actually needs rather than Qt's default equal (50/50) split of leftover space — a pane whose horizontal alignment is not FILL (e.g. LEFT with a fixed Lines/column count) should size to its intrinsic grid width, and the FILL pane should absorb all the remaining space. Confidence: 0.55
- Works on the same files while the agent is editing (e.g. tweaking QML layouts and config concurrently) and expects the agent to re-read files before editing and leave the user's in-flight changes untouched rather than clobbering them. Confidence: 0.5
- Prefers state to be owned and scoped by the component that uses it (e.g. selection mode/shared selection state belongs to each pane/view, not a single window-global instance) — global state scoped to the whole window is treated as a defect when it causes duplicate/conflicting UI (e.g. several selection toolbars at once). Confidence: 0.6
- Prefers toolbars/controls to adapt responsively to available space, collapsing text labels to icon-only (keeping tooltips) when the container is too narrow rather than overflowing or truncating. Confidence: 0.55
- Expects a fix to be validated against the real user interaction path (the app exercised the way a user actually would), not just a clean build or a synthetic/programmatic approximation of the scenario — a change that compiles and passes a hand-simulated check but breaks the genuine path is treated as an unfinished regression. Confidence: 0.6
- Reports bugs tersely and symptom-focused — states the reproduction condition and the observed broken behavior (e.g. "when selecting multiple items and right clicking, all actions get grayed out") without prescribing a cause or a fix, trusting the agent to reproduce and diagnose it. Confidence: 0.45
- Expects standard desktop keyboard/menu behavior to work end-to-end: Alt should reveal mnemonic underlines, Alt+letter should open menus and activate items, and pressing Alt while a menu is already open should not dismiss it. Confidence: 0.6
- Expects UI fixes to hold across all equivalent entry points and configurations, not just the primary path — e.g. a keyboard/menu fix must work in context menus as well as the menu bar and regardless of the NativeMenuBar config setting. Confidence: 0.55
- Prefers drag-and-drop feedback to be targeted and explicit: highlight the exact drop slot/target under the cursor and make the tooltip name the actual operation (e.g. "Reposition"), rather than a broad highlight of the whole destination or a generic action label. Confidence: 0.7
- Expects view/sort configuration changes to apply immediately — changing a sort or view mode should refresh/reload the folder right away so the new mode is visible without a manual reload or reopen. Confidence: 0.7
- States feature/enhancement requests tersely and behavior-first, describing the desired end result (what should happen or what the UI should say) without prescribing a cause or implementation — matching how they report bugs. Confidence: 0.5
- Prefers menu actions to be nested inside the submenu they logically belong to (e.g. a "Reset Manual Positions" action belongs in the sorting submenu that controls that feature, not at the top level) and to be disabled/greyed out when they would have no effect (e.g. no saved positions exist). Confidence: 0.5
